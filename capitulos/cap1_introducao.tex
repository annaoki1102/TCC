A lógica computacional é a base do desenvolvimento de software. Ela define as regras, as decisões e as condições que fazem um sistema se comportar de determinada forma. Para ser usada, essa lógica precisa ser escrita de algum jeito que o computador consiga executar.

A abstração ajuda a lidar com a complexidade da computação. Com ela, deixam-se de lado os detalhes de uma implementação para olhar só o que importa em um problema \cite{abelson1996}. Por isso, uma mesma lógica pode ser escrita de formas diferentes. Uma condição, por exemplo, pode aparecer como um \texttt{if} em uma linguagem de programação, como um losango em um fluxograma ou como um nó em um sistema visual. A forma muda, mas o comportamento esperado continua o mesmo. Neste trabalho, chama-se de \textbf{lógica} o conjunto de regras e decisões, e de \textbf{representação} a forma usada para escrevê-las. A programação visual, que usa elementos gráficos para construir programas, é um exemplo de representação \cite{myers1990,noone2018}.

Na prática, profissionais de tecnologia precisam passar uma mesma lógica de uma representação para outra. Isso acontece, por exemplo, quando uma regra escrita em uma fórmula de planilha precisa virar um código, ou o contrário. Nessa passagem, a lógica não pode mudar. Se uma condição for esquecida, o resultado fica errado.

Esse problema apareceu em um questionário exploratório aplicado a quatro profissionais de Tecnologia da Informação. Um deles, que usa programação como apoio técnico no trabalho, relatou que precisa levar fórmulas de planilha para Python, e também o caminho inverso, mantendo o mesmo resultado. A maior dificuldade são as fórmulas com condições aninhadas, isto é, um \texttt{SE} dentro de outro \texttt{SE}. Nelas, a lógica fica escondida na sintaxe e é fácil deixar passar uma condição. Hoje ele faz esse trabalho à mão: lista as condições, reescreve a solução e testa. Segundo ele, isso gera retrabalho, e a perda de tempo é a consequência mais importante. Dois outros participantes relataram dificuldades parecidas ao adaptar uma lógica entre tecnologias diferentes. Como foram só quatro respostas, o questionário mostra que a necessidade existe, mas não permite dizer que todos os profissionais passam por isso.

A literatura mostra que passar código de uma linguagem para outra é uma tarefa difícil, mesmo para modelos de Inteligência Artificial. \citeonline{pan2024lost} avaliaram a tradução de código entre cinco linguagens e consideraram uma tradução correta apenas quando o código compila, executa e passa nos testes. Nesse estudo, o percentual de traduções corretas ficou entre 2,1\% e 47,3\%, conforme o modelo. Isso mostra que gerar um código que parece certo não basta: é preciso verificar se ele se comporta como o original. Nos trabalhos consultados até agora, não foi encontrado um estudo que trate especificamente da conversão de fórmulas de planilha com condições aninhadas para código.

Diante disso, o \textbf{problema} deste trabalho é a dificuldade de converter fórmulas de planilha com condições aninhadas em código sem perder nenhuma condição, e de conferir se o resultado continua igual.

O \textbf{objetivo geral} é desenvolver e avaliar um protótipo que converte fórmulas de planilha com condições aninhadas em código Python e mostra a lógica em forma de fluxograma. Os \textbf{objetivos específicos} são:

\begin{itemize}
    \item definir quais tipos de fórmula o protótipo vai aceitar;
    \item representar a lógica da fórmula em uma estrutura independente da forma em que ela foi escrita;
    \item gerar, a partir dessa estrutura, o código Python e o fluxograma;
    \item verificar se o código gerado dá o mesmo resultado da fórmula em casos de teste;
    \item avaliar, com um profissional da área, se o fluxograma ajuda a entender a lógica.
\end{itemize}

A \textbf{solução proposta} é uma ferramenta pequena. Ela recebe uma fórmula, identifica suas condições e organiza essa lógica em uma estrutura em forma de árvore. A partir dessa árvore, a ferramenta gera o código Python e o fluxograma. Como os dois saem da mesma estrutura, a lógica é a mesma nas três formas: fórmula, código e fluxograma. Essa estrutura faz o papel de representação intermediária, ideia que vem dos estudos sobre abstração e representação da lógica. O uso de regras fixas ou de Inteligência Artificial para fazer a conversão será definido durante o desenvolvimento.

O público a que se destina são profissionais que usam planilhas e códigos no trabalho e precisam passar regras de uma forma para a outra. O profissional que relatou o problema será o principal usuário na avaliação.

Do ponto de vista metodológico, este trabalho é uma pesquisa aplicada, com desenvolvimento de um protótipo \cite{gil2002,prodanov2013}. As etapas são: pesquisa bibliográfica, levantamento de fórmulas reais e de exemplo, desenvolvimento do protótipo e avaliação. A avaliação terá duas partes: testes que comparam o resultado da fórmula com o do código gerado, e a opinião do profissional sobre o fluxograma. Ficam fora do escopo outras linguagens, programação por blocos e uma aplicação web completa.
