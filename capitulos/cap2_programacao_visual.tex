\section{Fluxogramas}

Os fluxogramas são uma das formas mais antigas de representar algoritmos de modo visual. Com símbolos padronizados e setas, eles mostram decisões, passos e caminhos de execução. Por isso, são muito usados para documentar e explicar uma lógica.

Um fluxograma é descritivo: ele mostra a lógica, mas não a executa. Para rodar, a lógica precisa ser escrita em código. Essa característica combina com o objetivo deste trabalho, que é usar o fluxograma para ajudar a entender e conferir a lógica de uma fórmula, e não para executá-la.

\citeonline{myers1990} diferencia a programação visual, em que o programa é construído com elementos gráficos, da visualização de programas, em que um programa já existente é mostrado de forma visual. Na literatura, a relação entre representações visuais e textuais é estudada principalmente no ensino de programação \cite{noone2018}. Neste trabalho, o fluxograma é usado como visualização de uma lógica que já existe.

\section{Fórmulas de planilha e condições aninhadas}

Em planilhas, as regras são escritas como fórmulas. A função \texttt{SE} recebe uma condição e dois resultados: o que vale se a condição for verdadeira e o que vale se for falsa. Quando existem mais de duas situações, um \texttt{SE} é colocado dentro de outro. É o que se chama de condições aninhadas. Por exemplo:

\begin{verbatim}
=SE(A1>10; "alto"; SE(A1>5; "médio"; "baixo"))
\end{verbatim}

Essa fórmula tem três resultados possíveis. Com mais níveis, ela fica longa e difícil de ler, porque as condições ficam escondidas dentro dos parênteses. Esse é o ponto em que é fácil esquecer uma condição ao passar a regra para outro formato, como foi relatado no questionário apresentado na introdução.

Essa mesma lógica pode ser organizada como uma árvore: cada decisão é um nó, e cada caminho termina em um resultado. A árvore não depende da sintaxe da planilha nem da do Python, e é a partir dela que a proposta deste trabalho gera o código e o fluxograma.

\section{Conversão de código e verificação}

Passar uma lógica de uma forma para outra exige que o comportamento se mantenha. Em estudos de tradução de código entre linguagens, uma tradução só é considerada correta quando o código compila, executa e passa nos testes \cite{pan2024lost}. Código que apenas parece correto não é suficiente.

Por isso, a verificação deste trabalho é feita com casos de teste. Os mesmos valores de entrada são aplicados à fórmula e ao código gerado, e os resultados são comparados. Se forem iguais em todos os casos, o código é considerado equivalente à fórmula para aqueles casos. Os testes mostram que o código funciona nos casos escolhidos, mas não provam que ele está correto em todas as situações possíveis. Por isso, a escolha dos casos é parte importante da avaliação.
